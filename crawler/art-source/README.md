# art-source/

Reference art that is **not** loaded by the game. Nothing in here is fetched at
runtime; `public/art/` is the only folder the loader reads.

## dcc-books-1-3-sheet.png

A 1536×1024 showcase sheet of *Dungeon Crawler Carl* characters, environments
and UI, supplied by the repository owner.

It is filed here rather than in `public/art/` because **it cannot drive the
game's cast**, for two reasons that are properties of the image and not of the
loader:

**It has no animation.** The game asks each character for 25 frames — five
facings (`s, se, e, ne, n`) × four walk frames plus an attack pose. This sheet
gives each character one or two *static* poses: Carl front and back, Donut
sitting three ways, most enemies once. There is no walk cycle on it to slice.
Importing it would produce a cast that slides around the field in a fixed pose.

**It is a contact sheet, not an atlas.** Characters sit at different sizes on
an irregular layout with captions between them, sized for looking at rather
than for cutting up. The game's own cast is 990×1260 *per character*; here the
entire roster plus tiles, items, effects and UI share 1536×1024, which puts a
character at roughly 40 px. Upscaling that to the 198×252 Carl is drawn at
would look worse than what the game paints for itself.

### What it is genuinely useful for

- **Reference** for repainting or re-commissioning the cast in a matching style.
- **Static, non-animated art**: the item icons, status icons, UI frames and
  tile details, which have no walk cycle to be missing. These would need
  cutting out individually and wiring as `sprites` entries in the manifest.
- **Princess Donut**, who is the one character the game still paints in code —
  she is a cat and the LPC library is humanoids. A static Donut is closer to
  workable than any of the others, since she has no walk cycle in-game either.

### Provenance

A fan-made sheet, supplied by the repository owner. *Dungeon Crawler Carl* is by
Matt Dinniman; this project is a non-commercial fan work, not affiliated with or
endorsed by him or his publishers. The art is not generated by this repository
and is not covered by its AGPL licence, so it is tracked separately here rather
than folded in with the project's own assets.

It sits outside `public/art/` because it cannot be loaded, not because it is
quarantined — see the two reasons above.
